# 門田匡陽アーカイブ — UI・UX 静的モック

[入口を開く](index.html) · [楽曲詳細](song.html) · [作品詳細](work.html) · [情報が少ないとき](states.html)

`guides/public-site-design.md` をもとに、既存フロントを参照せずに作った初回デザイン案です。本番アプリの実装ではなく、情報の優先順位・画面構成・回遊を検討するための HTML / CSS と小さな操作サンプルです。DB接続、外部通信、ビルド、追加の依存パッケージは不要です。

## 開き方

`index.html` をブラウザーで直接開けます。URLによる絞り込み状態の保持まで確認する場合は、リポジトリ直下から次を実行してください。

```sh
python3 -m http.server 4175 --bind 127.0.0.1 --directory mocks/public-site
```

ブラウザーで `http://127.0.0.1:4175/` にアクセスします。サーバー停止は Ctrl+C。

## デザインの判断

- **入口は活動の地図。** 大きなコピーのすぐ下に8名義のキャリアリバーを配置。色の意味をここで知り、各詳細でも同じ色を手がかりにできます。
- **調べる／彷徨うを同じ階層に。** 検索と Dig を全ページに配置。年表・一覧で絞り込む行動と、未知の記録へ移る行動を両方支えます。
- **楽曲を回遊の中心に。** 「曲の旅」は収録先、「演奏史」はステージでの記録。同一画面に置きながら見出しを分け、意味を混同させません。「4年ぶり」の発見からセットリストへ移動できます。
- **作品と版を分断しない。** 作品ページの主役は曲順。同じページの下で版を比較し、曲のページから該当版へ直接移動します。
- **情報量に応じて展開する。** 年表では月ごとのライブをまとめ、バージョン・人物の参加履歴・資料室は必要に応じて展開します。
- **読む余白を保つ。** クールな白／藍がかった黒、明朝見出し、等幅の年月、細い罫線。写真の装飾やダッシュボード風のカード群に頼らず、記録自体を主役にします。
- **詳細の末尾には次の入口。** 楽曲から作品とライブ、人物からプロジェクトと作品、会場から公演と定番曲へ。関連導線を2系統用意します。
- **モバイルでは形を変える。** キャリアリバーは縦の名義リスト、在籍図は人物別の小さな期間バー、人物相関は同内容のテキストリスト。楽曲表と演奏ヒートストリップのみコンテナ内の横スクロールです。
- **欠けた情報を偽らない。** 年／月／日の精度、ライブ演奏のみ、予定、未登録、検索0件を別々に扱います。開始時刻・料金など未確認の項目を空欄で並べません。

## 試せる操作

1. ホームの「黄金の鐘」→楽曲→収録先のハイライン版→作品の曲順→楽曲、という往復。
2. ライブ→会場→定番曲→楽曲、またはプロジェクト→伊藤大地→人物相関。
3. 作品／ライブ／年表などの絞り込み。条件はURLに反映し、再読込やURL直開きでも復元します。
4. ヘッダー検索で「黄金」「伊藤」「GARAGE」。該当なしの語で0件表示とクリア。
5. 楽曲一覧を「演奏回数が多い順」「曲名順」に並び替え。
6. 明暗テーマの切替。初期値はOS設定、手動変更は保存領域が使える場合に保持。
7. Digで代表的な詳細6画面のいずれかへ移動。現在と同じページは避けます。
8. 人物相関のサポート表示切替。図と代替リストが同時に切り替わります。
9. 年表の月別ライブ・バージョン・人物の関与・資料室の折りたたみ。
10. ブラウザー幅を390px前後にして、縦構成・ヘッダー・表の横スクロールを確認。

## サンプルの範囲と本番設計との違い

**データ検証用ではありません。** トップの集計数や「黄金の鐘：5バージョン」「下北沢GARAGE：57公演」などは設計書の例を利用しています。それ以外の年月・件数・在籍期間・作品の収録曲・バージョン・公演と人物の関係は表示用の仮データです。公開情報として転用しないでください。名義やタイトルが実在しても、組み合わせの正確さを保証するものではありません。

- 詳細ページは各種類1例です。一覧のすべての項目に詳細は用意していません。詳細未作成の項目はリンクを省くか、探し直せる一覧へ案内しています。本番では設計書のエンティティリンク規約を適用します。
- 活動期間のリバー・在籍図・年別棒グラフ・ヒートストリップ・人物相関は手で配置した例です。集計・レイアウト・ギャップ検出のロジックは実装していません。
- ホームの発見カードは固定3枚で、「順番を入れ替える」は順番のみ変更します。設計書の候補再抽選と「この日なんの日」、未来公演のトップバナーは未実装です。予定公演の表示例は状態見本にあります。
- 年表は3年の抜粋で、プロジェクト選択は単一選択。年アンカーのみを用意しています。本番の複数選択・月アンカー・リンクコピーは次段階です。
- 作品一覧は画像未登録時の代替タイポグラフィ表示を確認する案です。実ジャケットの縦横比混在・コンピレーション参加・catalog番号等は素材を揃えた次の検討対象です。
- 曲の旅とバージョン一覧は抜粋で、サンプル総数と表示件数は一致しません。初演・最終演奏・アンコール率も仮データです。
- 人物の参加記録はタブではなく、比較しながら読める折りたたみを提案しています。作詞・作曲に関与しない人物例のため「作った曲」は出していません。
- ライブ前後の導線は名義を絞った一覧へ戻ります。前後の公演詳細を歩く挙動は未実装です。
- 人物相関は2人物×3名義の静止SVG。ズーム・ホバーによる接続強調・外部名義の展開は未実装。モバイルでは同じ関係のリストを主表示にします。
- 検索は6件のサンプル内の部分一致です。Pagefindや本番の検索索引は導入していません。
- フォントはOS内の明朝・等幅フォントへフォールバックします。指定フォントの同梱や外部からの取得は行っていません。
- 独立した静的モックのため、URLは本番のslug構造ではなくフラットなHTMLです。
- `file://` ではブラウザーによってURL変更やテーマ保存が制限される場合があります。完全な操作確認には上記のHTTPサーバーを使います。

## タイポグラフィを修正する

書体・サイズ・行間・数値表示などの現状値と、決めてほしい内容を[タイポグラフィ レビューシート](typography-review.md)にまとめました。人が修正内容を記入するためのシートです。

## 次のレビューで決めたいこと

- ホームからの「年表」と「曲の旅」の優先度は適切か。
- 大判の作品表示と、密度の高い楽曲リストの使い分けは心地よいか。
- 楽曲詳細の「曲の旅 → バージョン → 演奏史」の順序で発見しやすいか。
- スマートフォンの名義リスト・人物相関リストで関係性が伝わるか。
- このタイポグラフィと余白を基準に、実ジャケットを加えても読みやすさを保てるか。

## 確認結果

- 19画面を幅320 / 390 / 768 / 1440pxのローカルChromeで確認。ページ全体の横はみ出し、JavaScript実行エラーなし。
- ホーム、楽曲、作品、作品一覧、年表、人物相関のスクリーンショットを確認。楽曲詳細では暗いテーマも確認。
- 検索、0件からの条件クリア、並び替え、フィルタ付きURLの直開き・再読込、版アンカー、折りたたみ、テーマ保存、Dig、人物相関の表示切替を確認。
- HTMLのローカル参照先・アンカーの存在、IDの重複、JavaScript構文を確認。
- HTMLファイルの直接表示も確認。ブラウザー間の網羅的な検証や、本番データを使った受け入れテストは対象外。
